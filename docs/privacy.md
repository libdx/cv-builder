# Public extraction and privacy boundaries

This repository was prepared as a new standalone extraction, with a fresh Git
history and no remote. Only reusable Python source, templates, tests, dependency
declarations, and presentation policy structure were carried over.

Replaced: candidate identity, all contacts, profile, education, full career
history and dates, evidence statements and provenance, practice inventory,
application example, avatar, public documentation, and content-specific test
expectations. Output filenames now follow the configured candidate name.

Excluded: the original Git history and config, portrait, reference documents and
images, generated exports, opportunity research, investigations, task records,
private application data, local environments, temporary files, and caches.

The initial audit checks source and documentation, filenames, the replacement
avatar metadata, generated HTML, selectable PDF text and metadata, and DOCX XML
including relationships and core properties. Git author/committer identity is
set to the fictional sample for the initial commit. No original identifiers or
private audit denylist are stored here.

This audit describes the initial sample extraction. It cannot guarantee future
commits will remain anonymous. Before public sharing, review `git diff --cached`,
tracked files, assets, remotes, commit identity, and every reachable commit.
Keep real CV work in a private copy. Ignoring a directory does not erase its
previous contents from history. Private disclosure flags are rendering rules;
they do not encrypt or conceal stored facts.
